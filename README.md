## 왜 만들었나

시중 앱들이 저한테는 잘 안 맞았습니다.

- **교재 문제를 넣을 수 없다.** 풀던 문제집을 그대로 쓰고 싶었는데 대부분 자기네 문제만 제공합니다.
- **필기가 안 된다.** 종이에서 하던 형광펜·밑줄·여백 메모를 화면에서 못 하니 지문 분석이 안 됩니다.
- **틀린 걸 모아주지 않는다.** 틀린 문제는 따로 옮겨 적어야 했습니다.

그래서 *교재를 내 데이터로 넣고, 종이처럼 필기하고, 틀린 건 자동으로 쌓이는* 도구를 만들었습니다.

---

## 주요 기능

**문제 관리**
- 리딩·리스닝·라이팅·스피킹 문제를 직접 추가 (직접 작성 / 사진 / JSON 가져오기)
- 라벨을 달아 교재별로 분류하고, 체크박스로 원하는 라벨만 골라 보기
- 사진을 올리면 AI가 문제 형식으로 변환

**필기**
- 지문을 왼쪽, 문제를 오른쪽에 나란히 두고 지문은 스크롤을 따라다님
- 드래그하면 그 자리에 색 선택창이 떠서 형광펜·밑줄·네모박스를 한 번에 적용
- 단어 아래에 메모를 달고, 나중에 다시 고쳐 쓸 수 있음
- 단축키: `Ctrl+H` 형광펜 · `Ctrl+U` 밑줄 · `Ctrl+B` 네모박스 · `Ctrl+M` 메모 · `Ctrl+D` 단어장

**문제 풀이**
- 실제 시험과 같은 화면 구성. 리스닝은 대본을 감추고 음성만 재생
- Reading Task 1은 빠진 글자 수만큼 칸을 그려서 실제 시험처럼 보이게
- 문제를 풀다 모르는 단어를 드래그하면 바로 단어장에 추가

**모의고사**
- 영역별로 저장해둔 문제 중에서 무작위로 뽑아 한 세트 구성
- ETS가 공개한 문항 수·시간 기준 (리딩 50/30분, 리스닝 47/29분, 라이팅 12/23분, 스피킹 11/8분)
- 시간이 끝나면 자동 제출, 리딩·리스닝은 자동 채점

**반복 연습**
- 단어 카드 (뜻·유의어·예문 AI 자동완성)
- 철자 연습 — `audit_____` 처럼 어간만 보여주고 나머지를 맞히기. 문제에서 틀린 빈칸이 자동으로 쌓임
- 전치사 연습 — `compare` → `with` 를 직접 타이핑. 막힐 때만 보기를 열 수 있고, 그러면 정답으로 세지 않음

**그 밖에**
- 라이팅 AI 첨삭 (TOEFL 공식 채점 기준 4항목)
- 화자별 목소리를 나눠 읽어주는 음성 재생
- 스피킹 녹음
- 다크모드, 모바일 대응
- 계정 로그인 후 기기 간 자동 동기화

### 왜 파일 하나인가

`index.html` 한 개에 약 6,000줄이 들어 있습니다. 일부러 그렇게 했습니다.

혼자 쓰는 도구라서 **어디서든 열리고, 아무것도 설치하지 않아도 되는 것**이 가장 중요했습니다.
빌드 단계가 없으니 파일을 고치고 새로고침하면 끝이고, 배포도 폴더를 끌어다 놓기만 하면 됩니다.
`npm install`이 깨질 일도, 의존성이 낡을 일도 없습니다.

대신 치른 대가가 있습니다. 파일이 커지면서 함수를 찾기 어려워졌고, 테스트를 붙이기 까다로워졌습니다.
지금 규모(6,000줄)가 이 방식으로 감당할 수 있는 한계에 가깝다고 보고 있습니다.

## 만들면서 풀었던 문제들

### 1. 필기 서식이 겹칠 때 깨지던 문제

형광펜 위에 **범위가 다른** 밑줄을 치면 네모박스가 여러 조각으로 쪼개져 보였습니다.
게다가 서식을 지우고 다시 칠하면 더 심하게 깨졌습니다.

원인이 두 가지였습니다.

- 브라우저의 `Range.extractContents()`는 선택 영역이 기존 `<span>`을 걸치면 그 span을 **둘로 쪼갭니다.**
  조각마다 테두리를 온전히 그리니 박스 가운데 세로선이 생겼습니다.
- 서식을 지우면 span이 풀리면서 **텍스트 노드가 조각난 채로 남았습니다.**
  그 위에 다시 칠하면 조각 수만큼 span이 생겼습니다. 이게 "지워도 계속 깨진다"의 진짜 원인이었습니다.

해결:

- 서식이 적용된 DOM을 **조각 배열로 평탄화**한 뒤 다시 조립하는 방식으로 바꿨습니다
  (`flattenExtracted` → `piecesToFragment`). 중첩 span이 생기지 않습니다.
- 같은 회차에 친 네모박스에 **그룹 표시**를 달고, 맞닿은 조각끼리는 안쪽 테두리를 없애
  쪼개져도 한 덩어리로 보이게 했습니다.
- 편집이 끝날 때마다 텍스트 노드를 병합하고 같은 서식의 이웃 span을 합칩니다.

조각난 텍스트 노드 6개를 가로질러 박스를 쳤을 때, 이전에는 박스가 6개 생겼지만 지금은 1개입니다.

### 2. 두 기기에서 각각 편집해도 잃지 않는 동기화

처음에는 나중에 저장한 쪽이 이기는 단순한 방식이었습니다.
집 노트북에서 문제를 추가하고 학교에서 필기하면, 둘 중 하나가 통째로 사라졌습니다.

**툼스톤(tombstone) 기반 병합**으로 바꿨습니다.

- 항목마다 id를 두고, 양쪽에 있는 것은 **모두 살립니다** (덮어쓰지 않음)
- 삭제는 지우는 대신 `{id: 삭제시각}` 기록을 남겨 다른 기기로 **전파**합니다
  (그냥 지우면 다른 기기가 "없어졌네, 내가 복구해줘야지" 하고 되살립니다)
- 삭제 기록은 180일 뒤 정리합니다

Supabase의 RLS(Row Level Security)로 각 사용자가 자기 행만 읽고 쓰도록 막아두어서,
anon key가 코드에 그대로 들어 있어도 안전합니다.

### 3. 모의고사 출제 — 지문은 중간에 자를 수 없다

실제 시험은 리딩 50문항입니다. 그런데 지문 하나에 문항이 여러 개라
**딱 50개를 맞추는 게 불가능**합니다. 5문항짜리 지문을 반만 낼 수는 없으니까요.

목표 문항 수를 채울 때까지 지문을 뽑되, **하나 더 넣는 게 목표에서 오히려 멀어지면 멈추도록** 했습니다.
결과가 목표보다 몇 문항 넘거나 모자랄 수 있고, 화면에 실제 시험 문항 수와 함께 표시합니다.

여기에 문제가 하나 더 있었습니다. 교재에서 변환한 데이터는 Hackers Test 한 세트가
**16문항 / 대본 8종**을 한 항목으로 묶고 있었습니다. 통째로 뽑으면 한 번에 16문항이 딸려왔습니다.
문제별 대본을 기준으로 **항목을 쪼개** 각 대본을 별개 지문으로 취급하도록 했습니다.
저장된 항목은 2개지만 출제할 때는 지문 17개로 셉니다.

## 구조

```
index.html      사이트 전체 (HTML + CSS + JS)
builtin.js      사이트가 기본 제공하는 문제
imports/        교재에서 변환한 문제 JSON
```

주요 함수:

| 함수 | 역할 |
|---|---|
| `renderAnalysisView` | 필기 화면 |
| `flattenExtracted` / `piecesToFragment` | 서식 평탄화·재조립 (중첩 span 방지) |
| `mergeSyncPayload` | 클라우드 병합 |
| `renderExamQuestions` | 리딩·리스닝 공용 문제풀이 |
| `renderMock` / `buildMockUnits` | 모의고사 |
| `buildCwDrill` / `buildPrepDrill` | 철자·전치사 연습 |

localStorage 키는 `toeflData`(문제·단어), `toeflProgress`(진도), `toeflAnnotations`(필기),
`toeflDeleted`(삭제 기록) 등으로 나눠 두었습니다.
